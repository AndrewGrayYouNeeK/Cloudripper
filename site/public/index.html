How it works

Three steps. Scanning only needs read-only access.

  1. Install

    Download a prebuilt binary for Linux, macOS, or Windows from GitHub Releases, or run one go install command.

  2. Connect read-only

    Scans need only read-only access. optimize, schedule, and scale change AWS, GCP, or Azure resources only when you pass --apply. --dry-run still wins if both are set. A live change asks for confirmation on a terminal, or --yes when stdin is not a terminal. Cloudflare mutations are refused.

  3. Scan & act

    You get inventory, spend (an actual total when a billing API responds, otherwise an estimate), and forgotten-bill matches. Chaos posts only when CHAOS_ENDPOINT is set. Slack or email alerts are sent only if you configure them.

$ go install github.com/AndrewGrayYouNeeK/Cloudripper/cmd/cloudripper@latest
$ cloudripper rip             # inventory what is running in your cloud accounts
$ cloudripper cost            # actual vs. estimated spend
$ cloudripper find-bills      # surface forgotten paid services
$ cloudripper --help          # see cost and chaos-test commands
Read-only scans. rip and cost do not change resources. optimize, schedule, and scale require --apply before they change anything, and --dry-run still wins if both are set. Cloudflare is read-only. Chaos does not use --apply; it posts only when CHAOS_ENDPOINT is set. The CLI calls each cloud's own APIs with credentials that stay on your machine. Your cloud data is never sent to us.

FAQ

Is CloudRipper really free?

Yes. The CLI is open source under the MIT license and free to use, including commercially. Paid plans are only for the optional hosted dashboard.

Is it safe to point at my cloud account?

Scans need only read-only access. optimize, schedule, and scale change AWS, GCP, or Azure only when you pass --apply, and --dry-run still wins if both are set. A live change asks for confirmation on a terminal, or --yes when stdin is not a terminal. Cloudflare mutations are refused. Chaos posts only when CHAOS_ENDPOINT is set, and production-looking names need --allow-prod.

Where do my credentials go?

The CLI runs on your machine and uses your local credentials to call AWS, GCP, Azure, or Cloudflare directly. Your cloud data is never sent to us. The waitlist form on this site stores the email you submit. Slack and email alerts run only if you configure them. find-bills talks to IMAP or Gmail only when you point it there.

Which clouds are supported?

AWS, Google Cloud (GCP), Microsoft Azure, and Cloudflare. Cloudflare inventory is read-only. Billing history needs Billing Read. Per-resource Cloudflare costs are unpriced.

What does find-bills do?

It looks through mail you configure (IMAP or Gmail, read-only) and an optional bank or card CSV for recurring paid services you may have forgotten about.
