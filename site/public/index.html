How it works

Three steps. Scanning only needs read-only access.

  1. Install

    One go install command gives you the cloudripper binary.

  2. Connect read-only

    Use a read-only role or key you already have. Scans never need permission to change or delete anything.

  3. Scan & act

    Get a list of waste, real spend, and forgotten bills. You decide what to turn off. Changes only happen if you pass --apply and confirm.

$ go install github.com/AndrewGrayYouNeeK/Cloudripper/cmd/cloudripper@latest
$ cloudripper rip             # inventory what is running in your cloud accounts
$ cloudripper cost            # actual vs. estimated spend
$ cloudripper find-bills      # surface forgotten paid services
$ cloudripper --help          # see cost and chaos-test commands
Read-only scans. Cleanup actions are off unless you pass --apply. Use ReadOnlyAccess and billing read-only policies on AWS (or the equivalent viewer roles on GCP and Azure). Your credentials stay on your machine.

FAQ

Is CloudRipper really free?

Yes. The CLI is open source under the MIT license and free to use, including commercially. Paid plans are only for the optional hosted dashboard.

Is it safe to point at my cloud account?

Scans only need read-only access, so with read-only credentials it can't modify or delete anything. Commands that change things need --apply and a confirmation, and chaos tests are opt-in with blast-radius limits.

Where do my credentials go?

Nowhere. The CLI runs on your machine and uses your local credentials to talk to your cloud providers directly.

Which clouds are supported?

AWS, Google Cloud (GCP) and Microsoft Azure.

What does find-bills do?

It looks through your receipts and an optional bank CSV export for recurring paid services you may have forgotten about, read-only.
